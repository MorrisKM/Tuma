Features

Everything Postman does.
None of the cloud.

One small, native app for designing, testing, documenting, mocking and load-testing your APIs. It works on a plane.

Your workspace is a folder

Collections, requests and environments are readable YAML files. Review API changes in pull requests, branch them with your code, and never lose work to a sync conflict again.

# Users API/create user.yaml method: POST url: "{{baseUrl}}/users" expect: status: 201 body: - { path: $.id, exists: true }

Fast, because it's native

Rust networking and the system webview instead of a bundled browser. Opens instantly, sips memory.

Runs your Postman scripts

pm.test, pm.expect, pm.sendRequest and friends, in a sandbox, in the app and in CI.

Load & security tests

Virtual users, p50/p95/p99 latency, passive security checks and a shareable HTML report.

Encrypted fields

AES-GCM/CBC, RSA-OAEP and hybrid RSA + AES: fields are encrypted as they're sent and decrypted as they arrive.

Docs and mocks from your requests

Turn a collection into OpenAPI, Markdown or a standalone HTML page. Start a mock server that answers with the examples you saved, so the frontend team never waits on the backend.

OpenAPI 3.1MarkdownHTMLtuma mock

More than REST

GraphQL with introspection and a schema explorer, WebSocket, server-sent events and gRPC by reflection or .proto. Every auth you need, proxies, client certificates and a cookie jar.

OAuth 2.0JWTDigestAWS SigV4OAuth 1.0

Secrets stay secret

Secret variables live in the OS keychain, never in your files, your git history or an agent's context.

Moves in with your data

Imports Postman, Insomnia, Bruno, OpenAPI, HAR and cURL. Exports back to Postman, any time.

Keyboard-first

Ctrl K finds anything, Ctrl ↵ sends, Ctrl S saves, Ctrl T opens a tab.

my-api/ ├─ src/ … └─ .tuma/ # tuma init ├─ workspace.yaml ├─ environments/ │ ├─ local.yaml │ └─ staging.yaml └─ Users API/ ├─ _folder.yaml ├─ create user.yaml └─ get user.yaml

Local-first

Your API lives in your repo, not on our servers.

There are no servers. There's no "us" between you and your requests.

  • 01
    Review requests like codeEvery change is a readable diff in a pull request.
  • 02
    The same tests, in CItuma test reruns every saved check and exits non-zero when one fails.
  • 03
    Nothing leaves your machineNo account, no telemetry. Tokens set by scripts stay in Tuma's data folder, out of git.
Built for AI agents

Your coding agent can test the API it just wrote.

Tuma ships an MCP server and a CLI. Claude Code, Cursor and other agents send requests, check responses against your OpenAPI spec, run load tests and save what passes as tests, all inside the hosts you allow. Secret values are never shown to them.

claude mcp add tuma -- tuma mcp
agent · tuma mcp
